## Analysis

**Behaviour.** `/app/cwl/bin/mangrove_workflow_for_cwl`, generated by ipython2cwl from
`mangrove_workflow_for_cwl.ipynb` (one binary per notebook). It searches Earth-Search for
Sentinel-2 L2A scenes in the bbox over the last `days_back` days below `cloud_cover_max`,
computes NDVI/NDWI/SAVI, thresholds a mangrove mask, applies the allometric model
(Biomass = 250.5 × NDVI − 75.2) and IPCC carbon accounting, and writes
`biomass_summary.csv`, `carbon_summary.csv` and `mangrove_mask.tif` into `output_dir`.

**CWL specifics.**
- Inputs are four floats for the bbox plus `cloud_cover_max`, `days_back`, `output_dir`
  (candidate: a single `eoap.cct.bbox` input, as done one level up by `parse_aoi`).
- `cloud_cover_max` is `float` here while the notebook annotates it `CWLIntInput`
  (the KindGrove application-package variant uses `int`): open question Q-W2-INT.
- Output `result` is a `Directory` (glob `outputs`), mapped by the transform to a STAC
  **Collection**. The run record shows the binary itself writes a STAC **Catalog**
  (`catalog.json`) with one Item (`mangrove-analysis-<timestamp>.json`) whose assets are
  `mangrove_mask.tif`, `biomass_summary.csv` and `carbon_summary.csv`: corrected (M-05).
- `ResourceRequirement.ramMax: 512`, while the run record's engine log reports
  `Max memory used: 2949MiB` for this step. Under an engine that enforces the limit
  (Calrissian on Kubernetes) the step is OOM-killed; cwltool alone does not enforce it.
- Image `ghcr.io/geolabs/kindgrove/mangrove-cwl:v0.0.1-rc7` (tag, not digest).
- `days_back` is relative to execution time: the same inputs select different scenes on
  different days. The scene actually used is exposed in the Item written by the tool
  (`properties.scene_id`, `cloud_cover`, `datetime`), not in any CWL output parameter.

**Provenance.** Opaque at the CWL level: only one activity can be recorded, while the
incubator example `KindGroveProvenance.ttl` (bblocks-openscience) describes nine
notebook-cell processes. The profile keeps the deployable granularity and records the
decomposition as a process-type annotation, not as sub-activities.

## Provenance view

Expressed against the generic provenance profile (`ogc.bbr.provenance.provenance`, a W3C PROV chain): one `prov:Activity` whose `activityType` is the process-type IRI, `qualifiedAssociation.hadPlan` pointing to the processDescription, input and output `prov:Entity` objects (literal parameters carry `value`, files carry `links`) and the engine / container image as `prov:SoftwareAgent`.
The run is also given as a `wfprov:ProcessRun` (`ogc.bbr.wf4ever.wfprov.ProcessRun`), because the generic profile has no step-level run (GP-1).

Gaps met here are listed in `docs/PROVENANCE-GAPS.md`.

Execution and provenance examples are built from a real `cwltool --provenance` run (CWLProv research object `w2-pinned`: the register's pinned W2 source itself (bblocks-eoap-cct c27c60d `mangrove-workflow.cwl#mangrove-workflow`) run with the profile's execute inputs, `cwltool --no-match-user --provenance ro --outdir out`, 2026-09-23, cwltool 3.1.20260108082145 on an arm64 macOS host, 126 s; scene selected by `days_back` on that day: S2C_46PGC_20260913_0_L2A), activity `main/step_1` (engine cwltool 3.1.20260108082145). Timestamps are UTC: cwltool records naive local times, the offset is taken from its engine log. Hosts under `ospd.example.org` are illustrative: job and result URLs are not those of a deployment.

## openEO equivalence

**Level: none.** Opaque: one ipython2cwl binary running the whole notebook. No single openEO process; each notebook stage has a closeMatch (decomposition). run_udf could wrap the binary but expects a data cube in and out, which this tool does not follow (it searches and downloads its own data).


| Stage | openEO | Level | Note |
|---|---|---|---|
| STAC search, Earth-Search sentinel-2-l2a, bbox, cloud cover, last N days | `ogc.openeo.processes.cubes.load_collection` | closeMatch |  |
| NDVI (nir-red)/(nir+red+1e-8) | `ogc.openeo.processes.cubes.ndvi`, `ogc.openeo.processes.math.indices.normalized_difference` | closeMatch | epsilon 1e-8 in the denominator |
| NDWI (green-nir)/(green+nir+1e-8) | `ogc.openeo.processes.math.indices.normalized_difference` | closeMatch |  |
| SAVI ((nir-red)/(nir+red+0.5))*1.5 | — | none | no stable process; composition of add/subtract/divide/multiply |
